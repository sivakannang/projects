TLS test certificates (mutual TLS: the server and client each present a certificate)
====================================================================================
For local testing only. Tested with OpenSSL 3.6.

Files
  ca.crt, ca_key.pem            CA that signs the other two. ca_key.pem is never deployed.
  server.crt, server_key.pem    server identity
  client.crt, client_key.pem    client identity
Never commit a *_key.pem file.

server.cpp and client.cpp expect these filenames, in the directory they run from.
The handshake fails unless the peer certificate matches "unipay" (commonName in
getSocketInfo), so change the code and step 2 together if you change that name.
The server also rejects clients with no certificate. To use TLS, set isSSL = _TRUE
in both files and generate all of these files. The .crt files in the repo are old,
and their private keys have been removed, so they can't be used.


1. Create the CA

openssl req -x509 -newkey rsa:2048 -nodes -keyout ca_key.pem -out ca.crt -days 3650 -sha256 \
  -subj "/CN=demo-ca" \
  -addext "basicConstraints=critical,CA:TRUE" \
  -addext "keyUsage=critical,keyCertSign,cRLSign"


2. Create and sign the server and client certificates

for n in server client; do
  openssl req -newkey rsa:2048 -nodes -keyout ${n}_key.pem -out $n.csr -subj "/CN=unipay"
  printf 'basicConstraints=CA:FALSE\nkeyUsage=digitalSignature\nextendedKeyUsage=%sAuth\nsubjectAltName=DNS:unipay,DNS:localhost,IP:127.0.0.1\n' $n > $n.ext
  openssl x509 -req -in $n.csr -CA ca.crt -CAkey ca_key.pem -CAcreateserial -out $n.crt -days 825 -sha256 -extfile $n.ext
done
chmod 600 *_key.pem


3. Verify

openssl verify -CAfile ca.crt server.crt client.crt
openssl x509 -in server.crt -noout -subject -issuer -dates -ext subjectAltName

Handshake test, without the C++ code. Terminal 1:
openssl s_server -accept 14433 -cert server.crt -key server_key.pem -CAfile ca.crt -Verify 2 -verify_return_error

Terminal 2 (should print "Verification: OK" and "Protocol version: TLSv1.3"):
openssl s_client -connect 127.0.0.1:14433 -CAfile ca.crt -cert client.crt -key client_key.pem -verify_return_error -verify_hostname localhost -brief


4. Java keystore (optional)

openssl pkcs12 -export -in client.crt -inkey client_key.pem -certfile ca.crt -name client -out client.p12 -passout pass:changeit
keytool -list -keystore client.p12 -storepass changeit
Java reads PKCS12 directly, so ImportKey.java is no longer needed.


Why the steps look like this
  - 2048-bit RSA and SHA-256: OpenSSL 3's default security level rejects 1024-bit
    keys ("ee key too small") and SHA-1 signatures.
  - subjectAltName: hostname checks use the SAN. The CN is only a legacy fallback.
  - -days on "openssl req" only applies with -x509. For a CSR, set it when signing.
  - "openssl x509 -req" needs no CA database, unlike "openssl ca" (and its openssl.cnf).
  - -nodes leaves the key unencrypted, which is convenient for testing only.
